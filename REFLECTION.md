# Reflection: Homework 3 Part 1

**Austin Jackson, CS 4354, Fall 2026**

**How the agent differs from the Homework 2 pipeline.** In Homework 2 Part 2, my Python script controlled every step: send the question, take whatever SQL came back, run it once, and compare the number. The model never saw the data or its own result. Here the model decides what to do next. It chose when to read the schema, which rows to inspect, when a query was ready for `check_answer`, and what to run afterward. My Python only runs the tools, keeps the database read-only, and enforces the 5-attempt limit.

**A decision the agent made on its own.** On Q7 (Real Madrid's total goals), the agent first tried `SUM(homeGoals) + SUM(awayGoals)` filtered to Real Madrid's matches, which returned 7. It had not called `check_answer` yet, so nothing told it that was wrong. It had already pulled the `Match` table and recognized that the query also added the opponents' goals. It rewrote the query with `CASE` so each side's goals only count when Real Madrid is that side, which returned 3. After that matched, it still listed Real Madrid's three matches so the total (2 + 1 + 0) could be confirmed by hand.

**Why a matching answer is not enough, and whether the evidence was convincing.** A match only shows the query is right on this data. On Q4, a query checking only `homeGoals IS NULL` would also return 1, even though the question requires both scores to be missing. The agent tested this itself by searching for matches with just one NULL score and found none. I found the evidence for Q4 and Q7 convincing because the agent looked at the actual rows and reached the answer a second way. Q6 was weaker: its checks mostly repeated the same GROUP BY logic, and its final report listed a duplicate-row check that does not appear in the tool log, so it described a check it never ran. The answer is still correct, since the primary key already prevents duplicates, but it shows the agent's own summary cannot be trusted alone. The execution log is the real evidence.
